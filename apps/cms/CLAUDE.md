## How data flows

**Read (current path).** Server Component → `getThing()` in `src/lib/<domain>-api.ts` →
`loomGetJson()` → `${BACKEND_URL}` (the :8090 wrapper, `http://localhost:8090` by default) →
envelope checked by `assertEnvelopeOk` → rows, or a thrown `BackendFetchError` that `loadOrBanner`
renders as a banner.

**Write.** Client component → `POST /api/crud { path, method, body }` → registry + sandbox-floor
guards → service token attached → the wrapper. Products additionally have dedicated bridges at
`/api/product/{create,save,upload-image}`.

**Read (legacy path, still live).** `'use client'` page → `apiClient` (axios, `Authorization` from
localStorage) → `unwrapResponseData()`. Both stacks run side by side.

`apps/api` (the new NestJS backend) is **not** in either path. Nothing in the CMS calls it today.
Full detail: `docs/frontend/cms/data-layer.md`, `docs/frontend/cms/auth-and-writes.md`.

## Rules for working here

1. **Never fetch directly from a page.** Reads go in the matching `src/lib/<domain>-api.ts` and use
   `loomGetJson` — that layer is the only place a GET endpoint path may appear. Writes go through
   `POST /api/crud`, and a new write endpoint must be added to `WRITE_REGISTRY` with an explicit
   `band`-or-`open` disposition or the forwarder refuses it.
2. **Never fabricate data to fill a UI.** Around 15 routes in this app shipped with invented values —
   a fake Java stack trace, "Uptime: 14 days, 6 hours", "Total bandwidth saved: 4.8 GB". Every one of
   those has a real backend endpoint that was simply never called. If you cannot get real data, render
   an honest empty state and record it in `docs/KNOWN-GAPS.md`. Never invent a plausible number.
3. **Do not remove the `Origin: localhost` header** sent by `loomGetJson` and by the `/api/product/*`
   bridges. It looks like dead cargo-cult code. It is load-bearing: the legacy backend applies
   `@NVerseDomainValidated` to 114 of its 249 controllers, and that check requires a **present and
   allowlisted** `Origin`. Removing it breaks production. See `docs/KNOWN-GAPS.md`.
4. **Do not add `@ts-nocheck`** to any file here.
5. **There IS a server-side guard now — and it still does not verify a JWT signature.**
   `src/middleware.ts` gates every page (redirect to `/login`) and every `/api/*` route (401 JSON),
   checking token shape and `exp` only. Treat it as a usability gate, not a security boundary; the
   backend is the only real authority. `/api/auth/login` verifies credentials against Loom and
   nothing else — the sandbox token is an *additional* credential requiring `CMS_SANDBOX_LOGIN=true`,
   a non-production `NODE_ENV`, and a configured `CMS_SANDBOX_LOGIN_EMAIL`/`_PASSWORD` match; it is
   never a bypass. **Do not reintroduce a default-token fallback** — that was an authentication
   bypass, fixed 2026-09-02. See `docs/frontend/cms/auth-and-writes.md` §1.4.
6. **New code gets tests.** `vitest.config.ts` + the MSW harness at `src/test/` are wired and
   `pnpm test` runs 206 tests across 17 files. MSW runs with `onUnhandledRequest: "error"` — an
   unmocked request fails the test rather than escaping to a live host. Do not relax that, and never
   put a production hostname in a test file.
7. **Lint is a ratchet.** `eslint.config.mjs` downgrades three rule families to warnings because this
   app had never actually been linted (`next lint` was broken and silently linted nothing). Those
   counts only go down. Clear a file's warnings when you touch it.

## Conventions

- Data-layer functions are plain exported functions returning precisely typed data — prefer a named
  interface over `any`, and never add a new `[key: string]: any` escape hatch.
- Error handling: six of the eight `*-api.ts` modules **throw** `BackendFetchError`; `whatsapp-api`
  returns a `Result<T>` and `custom-products-api` does both. Match the convention of the module you
  are in and say which one you are returning; do not add a third.
- A backend failure must never be rendered as an empty list. Let it throw and let `loadOrBanner`
  banner it, or return `ok:false` and branch on it.
- Toasts via `react-hot-toast`. Icons via `lucide-react`. Dates via `dayjs`. Styling is Tailwind v4.

## Before building a feature

Read its spec in `docs/features/`, make one task per acceptance criterion, write the test first, then
implement. Verify with `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build` — all four must be green.
Append a handoff note to the spec when you are done.
