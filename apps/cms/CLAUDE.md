## Where things are

| Path | Owns |
|---|---|
| `src/app/**` | 96 routes, App Router. Pages are `'use client'` and generally do their own fetching. |
| `src/services/*.ts` | 24 service files — one per domain. **All backend access goes through these.** |
| `src/lib/api.ts` | The axios `apiClient` singleton + auth interceptor. |
| `src/lib/api-helper.ts` | `unwrapResponseData()` — every response passes through this one choke point. |
| `src/lib/auth-service.ts` | JWT storage, login, authority resolution. |
| `src/lib/config.ts` | `ConfigurationService` — backend host and endpoints. |
| `src/context/AuthContext.tsx` | The only auth gate. Client-side, post-mount. |
| `src/app/api/backend/[...path]/route.ts` | Catch-all proxy to the legacy Java backend. |

## How data flows

Page → `SomeService.method()` → `apiClient` (axios, injects `Authorization` from localStorage) →
`/api/backend/[...path]` route handler → **live legacy Java backend** (`loom-v2.anuprerna.com`) →
response → `unwrapResponseData()` → page state.

`apps/api` (the new NestJS backend) is **not** in this path. Nothing in the CMS calls it today.

## Rules for working here

1. **Never fetch directly from a page.** Add or extend a method in `src/services/` and call that. The
   service layer is the only place endpoint paths may appear.
2. **Never fabricate data to fill a UI.** Around 15 routes in this app shipped with invented values —
   a fake Java stack trace, "Uptime: 14 days, 6 hours", "Total bandwidth saved: 4.8 GB". Every one of
   those has a real backend endpoint that was simply never called. If you cannot get real data, render
   an honest empty state and record it in `docs/KNOWN-GAPS.md`. Never invent a plausible number.
3. **Do not remove the `Origin` header override in `src/app/api/backend/[...path]/route.ts`.** It looks
   like dead cargo-cult code. It is load-bearing: the legacy backend applies `@NVerseDomainValidated`
   to 114 of its 249 controllers, and that check requires a **present and allowlisted** `Origin`.
   Removing it breaks production. See `docs/KNOWN-GAPS.md`.
4. **Do not add `@ts-nocheck`** to any file here.
5. **Auth is client-side only — do not assume otherwise.** There is no `middleware.ts` and no
   server-side guard. `AuthContext` redirects in a post-mount `useEffect`, so protected page code and
   its fetches execute *before* the redirect fires. Never rely on the guard for security; the backend
   is the only real authority.
6. **New code gets tests.** This app currently has **zero** tests, no vitest config, and no test
   script — that is a gap being closed, not a precedent to follow. Copy the working setup from
   `apps/storefront` (`vitest.config.ts` + `vitest.setup.ts`).
7. **Lint is a ratchet.** `eslint.config.mjs` downgrades three rule families to warnings because this
   app had never actually been linted (`next lint` was broken and silently linted nothing). Those
   counts only go down. Clear a file's warnings when you touch it.

## Conventions

- Services are static classes. Methods return unwrapped data, typed as precisely as you can manage —
  prefer a named interface over `any`, and never add a new `[key: string]: any` escape hatch.
- Error handling: 13 of 24 service files have no `try`/`catch` and let errors propagate to the caller.
  When you touch a service, handle its errors rather than extending the pattern.
- Toasts via `react-hot-toast`. Icons via `lucide-react`. Dates via `dayjs`. Styling is Tailwind v4.

implement. Verify with `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build` — all four must be green.
Append a handoff note to the spec when you are done.
