# Runbook: Incident

> **Status:** the observability stack this runbook assumes is not wired yet. `request-id` is
> generated by `apps/api/src/common/middleware/request-id.middleware.ts` but that middleware is
> never registered in `app.module.ts`, so no real request currently carries one; there is no pino
> log aggregation, no Sentry integration, and no uptime/health alerting beyond the bare `GET
> /health` endpoint. See `docs/KNOWN-GAPS.md`. Until that's built, fall back to whatever hosting
> platform (Vercel) logs and manual reproduction — steps 1-2 below are the target process once the
> tooling exists.

1. Grab the `x-request-id` from the report; trace it across storefront -> api -> worker (pino logs).
2. Check Sentry (errors/traces) and uptime/health alerts.
3. Mitigate (rollback route if user-facing). 4. Write a short post-mortem as an ADR if it changes design.
